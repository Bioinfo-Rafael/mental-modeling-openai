# 19_RealTime_Lag_v2 — 追加区間だけを変化の判定対象にする

2026-10-26 JST。19_RealTime_LAGの比較条件として作成。最初のDecision APIの検知対象だけを変更する。

## 変更点

入力は従来どおり40時点。前回の観測窓末尾より後に追加された区間だけで、新しい動作変化・発射があるかを判定する。それ以前の入力は背景として使う。回答は引き続き `NONE / A1 / A2 / BOTH`。

| 今回の窓末尾 | 入力全体 | 前回の末尾 | 判定対象 |
|---|---|---|---|
| 39（初回） | 0〜39 | なし | 0〜39 |
| 44 | 5〜44 | 39 | 40〜44 |
| 54 | 15〜54 | 49 | 50〜54 |
| 340（最後） | 301〜340 | 339 | 340のみ |

境界は `previous_end_step + 1` から `end_step` まで。前回の判定がNONE・3秒超・エラーでも、次の判定対象を広げない。各窓とmanifest・照合用CSVに `previous_end_step`、`target_start_step`、`target_end_step` を保存する。

ゲートプロンプトは元run `19_RealTime_LAG/results/pilot_20261026_v2/prompts/gate/` を基準に、対象区間に関する指示だけ修正。元本文は [prompts/baseline_gate/](prompts/baseline_gate/)、送信本文は [prompts/gate_v001/](prompts/gate_v001/)、差分と元ファイルのハッシュは [prompts/changes/](prompts/changes/) に保存した。

具体的には、窓全体を証拠として読む指示を維持し、「どこかに変化があるか」を「指定された対象区間に変化の開始点または新しい発射があるか」に変更する。対象区間以前に始まった変化が継続する、または後から明確になるだけでは陽性にしない。対象区間の指定は変化が存在するという意味ではない。

## 維持した条件

- 両段階とも `gpt-6-luna` のDecisions API。
- ゲートが3秒以内にA1/A2/BOTHなら、A0100とA0200の両方の目的を並列判定。最初の回答がA1だけでも両機を送る。
- 4・8・32択の3条件。選択肢・定義・並び順・目的プロンプトは19と同一。目的は窓全体を根拠に窓末尾の主目的を選ぶ。
- ゲートは3条件で共用。各選択肢数で2機を並列送信し、選択肢数の条件間は順番に計測。
- 各APIを独立に3秒で採否判定。3秒を超えたゲートは後段を送らず、3秒を超えた目的回答はその機体だけ表示しない。生応答と実測時間は保存。
- 再生上の目的到着時刻は「観測時刻＋ゲートの実測応答時間＋機体別送信開始の差＋目的の実測応答時間」。2段階の合計が3秒を超えても、各呼び出しが3秒以内なら採用。
- 古い窓の回答による上書き防止、連続する同じ目的の履歴追加抑制、末尾で録画を止めて回答を待つ表示も維持。

自由文のGPT-5.6 sol条件は本実験に含めない。これは4/8/32択の実測遅延を再現する条件である。

## 実行

リポジトリ直下から。planとexportはAPIへ送信しない。

```sh
# 初回の計画作成。同名runがある場合は再実行不要。
.venv/bin/python experiments/19_RealTime_Lag_v2/run.py plan --run incremental_20261026 --repeats 1

# APIキーを設定したターミナルで実行。環境変数がなければ非表示入力。
.venv/bin/python experiments/19_RealTime_Lag_v2/run.py execute --run incremental_20261026

# 中断後、開始済みリクエストを再送せず、未送信分だけ続ける。
.venv/bin/python experiments/19_RealTime_Lag_v2/run.py execute --run incremental_20261026 --resume

# 再集計とビューアへの公開（API送信なし）。
.venv/bin/python experiments/19_RealTime_Lag_v2/run.py export --run incremental_20261026

# 本文の確認例。
.venv/bin/python experiments/19_RealTime_Lag_v2/run.py request --run incremental_20261026 --query r01_end_0054_gate
```

元と同じ62窓、1反復でゲート62件＋陽性窓ごとに最大6件。結果はこのディレクトリ内 `results/<run>/` に分離して保存する。19の保存済みゲートは流用せず、新しいプロンプトで判定し直す。

閲覧は既存の `http://127.0.0.1:8130/viewer/`。「推定目的」の実験runで **v2 · 追加5step判定** を選び、4/8/32択を切り替える。実行中・終了後は「結果を更新」を押す。サーバーが起動していなければ従来と同じコマンドを使う。

```sh
.venv/bin/python experiments/13_LAG/viewer/serve.py
```

ビューアのキャッシュには実験ディレクトリ名を付け、旧19と同名のrunでも置き換えない。

## 検証と限界

```sh
.venv/bin/python -m pytest experiments/19_RealTime_Lag_v2/tests -q
```

構造テストは判定対象の重複・欠落、未来データの混入、初回と最終窓、元の目的プロンプト・選択肢・時間設定の一致、2機の並列送信、3秒境界、再生順序と旧runとの共存を確認する。

検知対象が重ならないことは、モデルが同じ事象を再検知しない保証ではない。特に、開始時点では証拠が少なく後から変化が確定する動作を見逃す可能性がある。重複率の低下と検知漏れの増加は実回答・人手のイベント確認で評価する。API計測はオフラインで行い、実測遅延を録画時計へ加算する方式を維持するため、継続した実並行送信時の混雑は再現しない。
