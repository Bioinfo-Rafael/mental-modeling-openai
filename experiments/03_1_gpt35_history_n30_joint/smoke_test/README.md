# Smoke test

本番の`common.make_plan()`で各Task × Metricのpromptを1件ずつ選び、上流の`evaluate_episode()`からローカルcapture backendまで渡す。`backend.complete()`が受け取ったmessageと計画済みmessageが完全一致することをassertする。

API clientの構築やAPI requestは行わない。

```bash
.venv/bin/python experiments/03_1_gpt35_history_n30_joint/smoke_test/run_smoke_test.py
```

`prompts/`の8ファイルには、本番計画から生成され、runtime capture backendへ実際に渡されたsystem/user messageを保存する。metadataは別blockとして末尾に付けており、API messageには含まれない。

## 既存promptとの比較結果

比較対象は次の3箇所である。

- `prompts/*.txt`：Experiment 03.1で実際に生成された8種類のmessage
- `experiments/01_prompt_preview/results/*.txt`：既存promptを使ったExperiment 01のH=5 preview
- `upstream/LLM-Xavier/llm_x/feedback.py`：question本文の定義と、Joint promptの移植元

結論は次のとおり。

1. 8ファイルすべてで、system message、5 stepのhistory、`Given the following...`と`Analyze the sequence...`のwrapperはExperiment 01と同一である。
2. MountainCarのNext/Last Actionはquestion本文もExperiment 01と同一であり、Joint化していない。
3. PendulumのNext/Last Actionだけ、既存のcontinuous no-binsをbaseに、既存continuous binsから10-bin定義を移植し、Joint出力用の接続文とmarkerを追加した。
4. 両taskのNext/Last Stateは、Experiment 01が使った二択版ではなく、既存の`MoreOptions`三択版をbaseにした。`INC / DEC / UNCH`とthreshold `1e-4`は新規ではない。新規なのはraw state valueとforward deltaの出力blockである。

## 共通部分の出所

system messageはquestion classから作られていない。既存task定義を`llm_x/prompting.py`の`system_prompt()`が整形したもので、Experiment 01と03.1で同じである。

user messageのうち以下も`llm_x/prompting.py:user_prompt()`による既存共通処理であり、変更していない。

```text
Given the following snippet of an episode generated by a trained reinforcement-learning agent:

<同じepisodeから取り出した5 stepのhistory>

Analyze the sequence to answer this question:
<feedback.pyでrenderしたquestion>
```

したがって、03.1固有のwording差分は最後の`<question>`部分だけである。

## Pendulum Action Joint

### Next Action

定義は`feedback.py:194-220`の`NextActionPredictionContinuousJoint`である。

#### [REUSED] continuous no-binsからそのまま再利用

移植元は`feedback.py:166-189`の`NextActionPredictionContinuousNoBins`である。

- stateからactionを予測する冒頭文
- action range `[-2, 2]`
- `[Reasoning]`、`[Prediction]`、`[Formatting]`
- actionをreal valueとして答える指示
- `predictions = [-1.52, 1.25]`の例

#### [COPIED FROM continuous bins] bin定義を移植

移植元は`feedback.py:91-114`の`NextActionPredictionContinuousBins`であり、これはExperiment 01のPendulum Next Actionが使用しているquestionでもある。

```text
10 discrete bins ranging from [-2, 2]:
[-2., -1.6), ... , [1.6, 2.]
```

bin境界列そのものと、bin indexが`0`から`9`であるという意味を移植した。

#### [MODIFIED]

bins版の「binだけを予測する」という排他的な文章はJointに合わないため変更した。

```diff
- You only need to predict which bin ...
+ Also predict which bin ...
```

また、no-bins版の「小数点以下2桁まで」という指示と、bins版の「単一のbin ID」という指示を、real valueとbin IDの両方を1 dimensionにつき1個返す文章へ統合した。

#### [NEW]

次のJoint出力接続文とmarkerは既存prompt内に存在せず、新規である。

```text
Action element [i] is also assigned a bin index from 0 to 9.
After the real-valued predictions list, return the corresponding bin indices using this final marker:
>>Final action bins: [1, 8]
```

### Last Action

定義は`feedback.py:517-543`の`LastActionPredictionContinuousJoint`である。構成はNext Actionと同じである。

- [REUSED] base：`feedback.py:489-512`の`LastActionPredictionContinuousNoBins`
- [COPIED] bin定義：`feedback.py:413-436`の`LastActionPredictionContinuousBins`
- [MODIFIED] `You only need to predict which bin`を`Also predict which bin`へ変更
- [NEW] `>>Final action bins: [1, 8]`を含むJoint接続block

Experiment 01はcontinuous bins版なのでbin定義は共通だが、raw continuous valueの出力部分はExperiment 01にはない。これは別の既存no-bins promptから移植した部分である。

## State Joint

Next/Last StateともMountainCarとPendulumで同じquestion classを共有する。taskによって変わるのはsystem message、history中の値、state dimensionであり、Joint wordingではない。

### Next State

定義は`feedback.py:821-848`の`NextStatePredictionMoreOptionsJoint`である。

#### [REUSED] MoreOptionsからそのまま再利用

baseは`feedback.py:795-817`の`NextStatePredictionMoreOptions`である。

- current state、action、rewardからnext stateを推定する説明
- historyのpatternとtransition dynamicsを参照する指示
- compact reasoningとdimensionごとのstep-by-step prediction
- `INC / DEC / UNCH`の三択
- `UNCH` threshold `1e-4`
- `predictions = ["INC", "DEC", "UNCH"]`
- 不確実でも三択のいずれかを選ぶ最終指示

Experiment 01が使用したのは`feedback.py:850-872`の`NextStatePrediction`で、`INC / DEC`だけの二択版である。そのためExperiment 01との差分に現れる`UNCH`関連の文章は、Joint用の新規文章ではなく、既存MoreOptionsからの再利用である。

#### [MODIFIED]

方向だけを答えるpromptではなくなったため、base冒頭の限定を最小限変更した。

```diff
- You only need to deduce whether each element ...
+ Deduce whether each element ...
```

#### [NEW]

以下のraw value / delta blockは既存promptからの貼り付けではなく新規である。

```text
Also predict the numerical value of each element of the target state.
Also predict the signed change of each state element,
defined in the forward time direction as delta_state = s{i} - s{j}.
>>Final state values: [v0, v1, v2]
>>Final state deltas: [d0, d1, d2]
All three lists must follow the same state-dimension order ...
```

render後は、smoke fileでは`s5 - s4`のように実際のindexへ置換される。

### Last State

定義は`feedback.py:1146-1174`の`LastStatePredictionMoreOptionsJoint`である。

- [REUSED] base：`feedback.py:1118-1141`の`LastStatePredictionMoreOptions`
- [MODIFIED] `You only need to deduce`を`Deduce`へ変更
- [NEW] target previous stateのraw value
- [NEW] 常にforward方向の`delta_state = s{k} - s{i}`
- [NEW] `>>Final state values`、`>>Final state deltas`、dimension順序の制約

Experiment 01が使用したのは`feedback.py:1176-1198`の`LastStatePrediction`二択版である。Last Stateでも`INC / DEC / UNCH`とthresholdは既存MoreOptions由来で、新規ではない。

Last Stateで予測対象は過去の`s{i}`だが、deltaの符号は逆転させず、時間のforward方向である。

```text
delta_state = later state - earlier state = s{k} - s{i}
```

## 最終的な出力形式

| 対象 | LLMへ要求する出力 |
| --- | --- |
| MountainCar Action | `>>Final action choice: [action_id]` |
| Pendulum Action | `predictions = [raw_action, ...]`と`>>Final action bins: [bin_id, ...]` |
| Next/Last State | `predictions = ["INC"/"DEC"/"UNCH", ...]`、`>>Final state values: [...]`、`>>Final state deltas: [...]` |

## まとめ

新しく書いた範囲はJoint出力を接続するための小さなblockに限定される。

- MountainCar Action：新規なし
- Pendulum Action：raw値部分は既存no-bins、bin定義は既存bins、新規は両者を同時出力させる接続文とmarker
- State：方向分類部分は既存MoreOptions、新規はraw state valueとforward deltaのblock
- system message、history、user wrapper：8ケースすべて既存経路のまま
