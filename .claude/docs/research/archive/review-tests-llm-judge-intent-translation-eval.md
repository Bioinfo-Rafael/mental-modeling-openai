## E2E assessment

`test_e2e_real_episode_production_adapters_event_log_judge_preview` does exercise the production adapters. The detector goes through `translator_cli.build_system_one_client` (real `SystemOneClient`, real `SystemOneDetectionModel`) over `httpx.MockTransport`; the translation layer goes through the production `OpenAIIntentModel` and `OpenAIResponsesClient` over a scripted SDK object. It asserts `len(server.requests) == 1 + DETECTOR_TICKS` and `len(translation_client.requests) == TRANSLATIONS`, then asserts the judge preview trajectory is byte-identical to the window the translation layer received. This claim holds. Limits: the judge itself is only previewed in the E2E (judge execute is covered separately with the production `OpenAIResponsesClient` in `test_eval_cli.py`), and the stub detector answer 0.1 never crosses the threshold, so no `detector_change` trigger flows through the E2E (covered in pipeline tests).

## Findings

### High

- [High] `tests/translator/test_tr_cli.py` (+ `tests/translator/test_tr_budget.py`): missing test that a detector budget that does NOT fit fails the preflight. Set `detector.input_token_budget` (or window/fields) so `check_detector_budget(...).fits` is False; assert `main()` returns `EXIT_FAILED`, stderr names `PipelineError`/`>= input_token_budget`, no run directory is created, and no client factory is called (`src/mtd_rl_xavier/translator/cli.py:177`, `pipeline.py` `check_detector_budget`). Also unit-test `BudgetFit.fits is False` and `margin < 0`. Why: `test_tr_budget.py` only asserts `fit.fits` for the default config. If the comparison were inverted or the check removed, nothing fails, and vLLM would silently drop the newest steps of an over-long state (the data-integrity risk the plan calls out).
- [High] `tests/translator/test_tr_cli.py` and `tests/evaluation/test_eval_cli.py`: missing `--run-name` validation tests, e.g. `../escape`, `a/b`, `.`, empty, `x y`, a leading `-`. Assert exit 1, `PipelineError`/`JudgeConfigError` naming `--run-name must match`, and that nothing is written outside `--output-root` (`translator/cli.py:407`, `evaluation/cli.py:296`). Why: this is the only guard between a CLI argument and a `mkdir` path. Today it has no test (grep for `must match`/`SAFE_ID` finds none in the CLI tests), so a regression becomes path traversal on a tool that writes `0700` run dirs next to private data. Add the same cases for the `SAFE_ID_PATTERN` ids in `translator/config.py:257` (scenario ids).

### Medium

- [Medium] `tests/evaluation/test_eval_cli.py`: `max_judged_events` equal to the matched count but smaller than the total event count. With the 5-event run and 2 key-pointed events, `limits.max_judged_events = 2` must succeed (preview and execute) and `= 1` must fail (already covered). Why: D36 says the cap "counts only events that have key points"; only the failing side is tested at CLI level, so a regression to `len(planned)` would pass the whole suite (it only shows up when the cap is between judged and total).
- [Medium] `tests/translator/test_tr_cli.py` (preview): the pipeline row "an upper bound above the cap only warns" has no test. Build a plan whose `translation_upper_bound > max_translation_calls` (and detector calls > `max_detector_calls`); assert preview exit 0 with the two warnings from `cli.py:267-275` in `preview.json`, and that the run is not rejected. Why: the plan lists it, and the failure mode (turning a warning into an error or dropping it) is invisible today. `grep warn tests/translator` returns nothing.
- [Medium] `tests/evaluation/test_eval_cli.py`: preview warnings other than `nothing will be judged` are untested: translator run status not `completed` (partial log), `translated_intent` excluded, `key_points` excluded, long-context calls (`cli.py` `_warnings`). Also assert the clean case keeps `warnings == []` (already done). Why: these warnings are the only signal that the judge is scoring a partial or blind input.
- [Medium] `tests/evaluation/test_eval_cli.py`: cost arithmetic is asserted only as `> 0` (`cost_usd_upper_bound`, `approx_cost_usd`). Add exact-value tests for `_priced`/`_usage_cost`/`_estimate` with a hand-computed fixture: cached input priced at `cached_input`, the long-context multipliers applied above `long_context_threshold_tokens` (at, below, above), output priced at `max_output_tokens`. Why: wrong rates would pass silently, and this number gates a paid run.
- [Medium] P0 (`tests/test_mentalmodeling_layout.py` or a new test): no test that `.gitignore` covers `.txt .md .yaml .jpg .png .json .jsonl` under `/private/translator`, `/private/evaluation`, `/outputs/translator`, `/outputs/evaluation`, and none that the built wheel contains `mtd_rl_xavier.{lag,llm,translator}` (the `evaluation` package is not in `[tool.setuptools] packages`; confirm that is intended). Why: the ignore rules are what keep real scenarios and run outputs out of git. Note: the repo root reported "not a git repository" to this reviewer, so a `git check-ignore` test must skip or use `git -C` only when `.git` exists, and a wheel test needs `uv build` (needs user approval if it fetches anything).
- [Medium] `tests/lag/test_lag_contract.py`: untested `LagDataError` branches in `src/mtd_rl_xavier/lag/dataset.py`: `CSV columns differ from manifest` (:162), `Expected one episode with unique step/object keys` (:168, :250, duplicated key or two episodes), `Select records from one episode at a time` (:233), `Duplicate requested step or object ID` (:236). Also `render_*` `Reserved/Unknown fields` and `Unknown object IDs` are covered only by bare `pytest.raises(RenderError)`. Why: they are the integrity checks on the data the whole feature renders.
- [Medium] `tests/translator/test_tr_layers.py`: `SystemOneDetectionModel` branches not tested: `question_id does not match the client's question` (`detector.py:154`), `detector answer is not a noul answer` -> `ModelCallError(error_type="ProtocolError", uncertain=False)` (:174), and `SystemOneBudgetError` (pre-send bound / `usage.input_tokens >= budget`) mapping to a non-uncertain `ModelCallError` with `raw` kept. Why: these decide whether a run stops as `failed` or `uncertain`, which controls whether the operator may resend.

### Low

- [Low] `tests/lag`, `tests/translator`, `tests/evaluation` parametrized `pytest.raises(Error)` without `match` (e.g. `test_parse_rejects_anything_else` in layers and in contracts, the `lag` invalid-window and invalid-argument lists, `test_malformed_key_points_file_is_rejected`): add `match=` per case so a case cannot pass for a different reason. A probe of the judge parser cases (`.../scratchpad/tests/probe.py`) showed each currently fails for its intended reason, so this is regression-hardening only.
- [Low] `tests/llm`, `tests/translator`, `tests/lag`: no autouse offline guard. Only three evaluation tests use the opt-in `offline` fixture (patches `socket.socket.connect` and `getaddrinfo`). Move it to a shared autouse fixture so a future unmocked call fails loudly instead of reaching the network. Currently no test was found that touches the network.
- [Low] Speed (`.claude/rules/testing.md` says < 100 ms/unit test): 46 of 749 tests exceed 100 ms (lag 23, translator 10, evaluation 12, llm 1; about 57 s of the 58.7 s run). Largest: `test_tr_budget.py::test_default_config_fits_every_tick_of_every_episode` 17.2 s setup, `test_e2e_real_episode_production_adapters_...` 4.9 s, `test_preview_builds_no_client_reads_no_credential_and_writes_artifacts` 3.6 s, and ~1 s each for the `test_render_lag17_jsonl_bytes_equal_workspace_17_window` parity cases. They are integration tests on the real 13_LAG episodes, so justified; consider a `slow` marker. Fragility note: the lag parity tests import and read `workspace/13_*` and `workspace/17_*` sources, which belong to the user's concurrent work; a change there fails these tests without any bug in this feature.
- [Low] `tests/evaluation/test_eval_cli.py`: no test runs `--execute` on a log produced by the production Translator adapters (judge execute uses the fake-layer run). Optional: extend E2E #2 to also run the judge with a scripted `OpenAIResponsesClient` and assert the sent trajectory equals the translation layer's input.
- [Low] `src/mtd_rl_xavier/translator/schema.py:200` (`a translation needs at least one trigger reason`): no test constructs a translation event with an empty reason list. A one-line `pytest.raises(ValueError)` test is enough.
